## Assignment 1: Flocking + Spatial Partitioning

### Flocking
Flocks follows 3 core steering behaviors combined in a **Blended Steering** behavior:
* **Separation:** Avoid neighbors.
* **Cohesion:** Steer towards neighbors.
* **Alignment (Velocity Match):** Match neighbors' velocity.

Additionally, 2 more behaviors shape the flock's general movement:
* **Seek:** Move towards a target.
* **Wander:** Move to a random position on a circle in front of the agent.

![flocking_normal](https://github.com/user-attachments/assets/cc01c0fa-c0cc-41b6-9e33-240405b23c9d)

### Priority Steering
To add complexity, an enemy agent is introduced that the flock tries to avoid using a specific behavior:
* **Evade:** Move away from the predicted position of the moving target.

This behavior must overrule all other behaviors. Therefore, it is implemented using **Priority Steering** with the following evaluation order:
1. **Evade**
2. **Blended Steering** (The 5 behaviors mentioned above)

![evasion](https://github.com/user-attachments/assets/471ebf0c-26a9-473d-89ef-ff7115cbc83c)

### Spatial Partitioning
Normally, every update, each agent checks if every other agent is close enough to become a neighbor. This is an expensive task with a complexity of **O(n²)**. 

**Spatial Partitioning** improves this operation by dividing the world space into a grid of cells. Instead of checking all agents, an agent only checks which cells overlap with its neighborhood radius. It then only evaluates the agents within those specific cells, drastically improving computational performance for large flocks.

## Assignment 2: A* Pathfinding + Navigation Meshes

### Graphs
Graphs are data structures made up of nodes and connections. In pathfinding and navigation, graphs allow agents to move from one node to another by traveling along valid connections.

### A* Pathfinding
A* pathfinding is an algorithm used to find the shortest path between a start and target point.

In this project, A* is applied to a weighted graph to account for terrain types:
* **Blue tiles (Water):** Block the path entirely.
* **Orange tiles (Mud):** Have a larger weight because they are harder to cross.

![AStar](https://github.com/user-attachments/assets/cfa1869f-7df2-41b0-8e92-37019829edad)

### Navigation graph
Instead of using a standard waypoint graph, a navigation graph allows agents to move freely within a continuous walkable space. 

The navigation polygon is made up of triangles. A navigation graph is generated by creating a node at the center of each shared edge between triangles. Connections are then defined by linking all nodes within a triangle. To navigate, an agent adds its start and end positions as temporary nodes to this graph and runs the A* algorithm to find a valid route.

### Path Smoothing (SSFA)
The raw path generated by node-to-node navigation is rarely optimal and often results in zigzagging movement. To resolve this, the **Simple Stupid Funnel Algorithm (SSFA)** is applied.

SSFA treats the shared edges of the triangles crossed by the path as "portals" (each with a left and right point). The algorithm walks down the path, creating a funnel defined by a left and right leg. If the legs cross over each other, a corner point (apex) is added to the final path, and the funnel restarts. The result is a much shorter, natural, and straight path.
